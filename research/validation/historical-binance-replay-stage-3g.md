# Historical Binance Spot Replay Integration — Stage 3G

## Scope

This stage adds a deterministic replay driver to the strategy repository. It consumes caller-supplied normalized Binance Spot kline arrays for Weekly, Daily, 4H and 1H and evaluates the causal multi-timeframe strategy at an ordered list of UTC millisecond timestamps.

## Architecture boundary

- The application/data adapter remains responsible for downloading Binance historical klines, pagination, rate limits, retries, caching and symbol metadata.
- This repository remains pure strategy/research code: no HTTP client, credentials, browser APIs, database or exchange SDK.
- The replay driver emits chronological research decisions only. It does not submit orders or simulate fills.
- Event-driven/portfolio backtests remain a separate subsequent step and must use next-bar execution after a close-based signal.

## Temporal policy

At each evaluation timestamp, the existing causal MTF builder receives the full supplied arrays but admits only rows whose Binance close time is strictly earlier than the evaluation timestamp. A candle closing exactly at the evaluation timestamp is not admitted. This is intentionally conservative and avoids using a candle before its close is observable.

Evaluation timestamps must be finite and strictly increasing. Missing timeframe arrays and invalid timelines are rejected. Insufficient or invalid historical context remains fail-closed as WAIT.

## API

`runHistoricalMtfReplay(input, evaluationTimes, options)`

Input keys: `weekly`, `daily`, `h4`, `h1`. Each value is an array of Binance kline rows or normalized candle objects accepted by `normalizeCandles`.

## Limitations / release gates

1. This module does not fetch Binance data. The application adapter must supply complete, chronologically ordered historical klines.
2. No exchange data has been downloaded or performance result generated by this commit.
3. No fills, fees, slippage or portfolio accounting occur in this driver; emitted decisions must be passed to the event-driven simulator with conservative next-bar execution.
4. Validate symbol/timeframe alignment, missing candles, duplicate timestamps, pagination boundaries and historical data completeness in the application adapter.
5. Run causal prefix invariance and untouched holdout over real historical data before making any performance or readiness claim.
